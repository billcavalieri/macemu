# New World PPC JIT implementation plan

Started October 2, 2026, from the work sequence in [the PPC JIT report](NW-PPC-JIT-REPORT.md). The report's September 30 findings are the review baseline, not the current implementation status.

Correctness and independent validation precede new optimizations. Existing PPC and host 68k JIT defaults remain enabled; diagnostic overrides and explicit preference disables retain their meanings. Candidate builds and guest tests use private build directories and cloned VM media.

## First memory milestone

All memory helper exits now use a common record: the emitter-maintained faulting `pc`, exit cause, logical `fault_ea`, `fault_width` and `fault_st`. Live DSI recovery uses the recorded subaccess width instead of reconstructing it from an incomplete opcode list. Physical fast-path helpers receive the original logical address as well as PA.

Failed atomic stores preserve CR0 and the shadow reservation. A completed conditional store that modifies executing code commits EQ/SO and releases the reservation, then exits on SMC. FP/vector callback outputs are staged privately until success. `lmw` retains successful earlier register loads while preserving the destination whose access failed. RAM bounds arithmetic uses widened values so a high address cannot wrap into the fixture's valid range.

Regression testing also found an ARM64 encoding that compared W8 although the fault status was in W10. All eleven affected update checks now encode their intended register explicitly. Store-update SMC tests cover each supported store form.

The live vector-store callback previously reused scalar store callbacks and could stop after its first word on SMC. It now completes the probed aligned 16-byte store before invalidating and reporting the exit. Broader string/multiple/cache-line partial-completion semantics remain an audit item; this milestone does not certify all multi-access instructions.

Release qualification exposed a separate AltiVec startup-probe ABI defect. Its generated function now preserves x19, which is callee-saved under AAPCS64. The probe mapping is scoped so every return releases it and restores the enclosing compiler's writable-code state. Acceleration remains enabled during normal regression runs.

## FP environment and timer milestone

Control-register expectations follow the [PowerPC Programming Environments manual](https://www.nxp.com/docs/en/user-guide/MPCFPE_AD_R1.pdf), notably FPSCR controls and instruction listings in chapters 2 and 8, and decrementer request/delivery semantics in chapters 2 and 6.

Scalar FP instructions now own a bounded host FP environment. The KPX interpreter and JIT arithmetic helpers select RN from guest FPSCR for the instruction and restore both host control and accrued exception flags on return. ARM64 saves FPCR/FPSR directly and disables host traps, flush-to-zero and default-NaN during guest arithmetic. The optional inline scalar path follows the same policy, restores host state before its classification helper, and retains double FPR operands until result rounding. Fused multiply-add emission remains fused. Integer blocks and host callbacks retain the caller's environment, and nested FP scopes restore their outer owner.

FPSCR writes recompute the derived FEX/VX summaries independently of the optional arithmetic-exception tracking build switch. Direct writes cannot manufacture those summary bits. `mtfsb1` raises sticky FX when a new exception cause is set; `mcrfs` recomputes summaries after clearing the copied causes. Independent KPX tests additionally found and fixed two `mtfsfi` defects: field immediates were not shifted into their destination, and field-zero writes incorrectly excluded FX. Record forms receive the resulting summary nibble.

DEC requests now arise on timer/sign transitions and remain pending until delivery. A still-negative DEC does not request another exception after delivery. Full 64-bit elapsed time detects a crossing even across an entire 32-bit counter wrap. DEC samples use the host clock, so software TB writes do not advance or rewind DEC. The interpreter sampling divider belongs to each CPU instance.

Live JIT DEC reads and writes now use a CPU-owned callback at the instruction, including privilege checks, elapsed-time sampling and requests from writes. Each access ends its block; intermediate writes cannot disappear inside a shadow or be reapplied by a later chain commit. Both native tail calls and the C successor loop use one pending-event guard for enabled external/DEC exceptions and actionable CPU special flags. The existing internal KPX JIT-exit flag remains distinct from a host/guest event.

The host suite exercises all four guest RN modes against all four host rounding modes, three FPSCR writer forms, positive/negative boundaries, integer conversions, division, and cancellation-sensitive fused multiply-add variants. It uses literal expected IEEE results, checks host callbacks after FP work and fault returns, and covers nested scopes, host FZ/DN controls, signaling-NaN comparisons, subnormal classification and explicit FPSCR/CR expectations. These tests run with scalar inlining both off and on.

`tools/run_ppc_core_tests.py --build-log <isolated-app-build.log>` links a private alternate entry point against the actual KPX decoder/instruction objects and freshly compiled CPU integration. It replaces only the CPU's host-clock reference with a deterministic test clock. The executable initializes no UI or guest media. Its independent expected-state cases cover RN, FPSCR summaries, DEC crossing/wrap/delivery, retained requests across positive writes and EE masking, external priority, rfi, CPU flags, TB writes and generated DEC privilege/fault exits. This is independent KPX execution coverage; it does not repair the separate live PPC VERIFY isolation defect.

## Isolated live VERIFY milestone

VERIFY now executes the actual KPX interpreter first and keeps that result authoritative. It records ordered logical addresses, instruction PCs, widths, directions, returned values, stores and translation failures. The native shadow then consumes the observations with no live CPU, RAM pointer, device callback or populated DTLB. It compares store values and the complete observation sequence as well as registers and precise exits. Wrong addresses, order, direction, widths, missing accesses or store values fail comparison. Reference effects never run twice, including after a native replay failure.

This first allowlist covers supported scalar integer/FP calculations, branches, user LR/CTR/XER access, scalar integer/FP memory and multiple-register memory. Privileged/timer, reservation/atomic, string, delegated VMX and vector memory operations are explicitly counted as `skip_effect`, not as verified passes. Guarded native helpers also reject those operations during replay: a stale compiled block must not mutate shared translation generations or flush live caches simply because its newly fetched reference opcodes are safe. The native shadow still loads full register state and disables both chain paths. Production selective masks, chains, independent translation replay and broader system effects remain completion gates for stage 2.

Captures are bounded to sixteen distinct failing PCs per process at `/tmp/nw-ppc-verify-<pid>-<capture>.txt`. They contain input/reference/native registers, reference instructions, cached first opcode, fault metadata and access observations, with no host addresses. `tools/run_ppc_core_tests.py --build-log <complete-isolated-app-build-log> --replay <capture>` regenerates native code and compares it against the captured reference without a VM. A stale cache entry may disappear on fresh compilation; that distinction is diagnostic evidence rather than an instruction-correctness failure being suppressed. Automatic reduction and capture of the complete originally cached source remain future work. The checked-in `ppc_verify_fctiwz.capture` is a manually reduced two-instruction regression and runs automatically with the core suite.

The new verifier exposed three concrete issues:

- `fctiw`/`fctiwz` used different upper FPR words in KPX and the JIT. The ISA leaves that word unspecified; both engines now choose signed extension consistently, including KPX's invalid-result branch. JIT NaN conversion explicitly produces the integer-indefinite word instead of invoking an undefined host float-to-integer cast. Defined low-word integer results are unchanged. This removes differences in subsequent full-width stores; it is a consistent emulation policy, not evidence of an ISA upper-word defect.
- `stmw` stopped at its first completed SMC store. It now completes the instruction's remaining stores, preserving a later DSI's precise subaccess if one occurs, and then exits before the following instruction.
- Host `MakeExecutable`/`FlushCodeCache` publication reached only the legacy KPX cache. CPU range invalidation now translates the published instruction pages without PTE access recording and notifies both New World JITs. Guest icbi uses the same bridge with its own source label. Empty ranges and unrelated pages remain intact.

Final host evidence:

## String replay and production transition milestone

Live VERIFY now records and replays `lswi`, `lswx`, `stswi` and `stswx`. Ordinary string loads retain the KPX word/halfword/byte transaction widths, so replay checks device access order and returned values without calling the device twice. Each destination register commits only after its bytes complete; previously completed registers and byte stores remain visible on a later fault. Immediate NB=0 selects 32 bytes, indexed counts retain the existing seven-bit XER policy, and register wrapping is covered. Zero indexed counts remain the emulator's existing no-transfer policy, not a claim that all architectural invalid forms are legal.

A new protected-boundary fixture exposed a reference host fault: the MMU translation routine validates the starting address, and an unaligned word/halfword string read could pass its permission check and read host memory beyond that translated page. Both KPX and native string loads now split reads at 4 KiB boundaries and translate each subaccess independently. A valid next BAT mapping to a different physical page is checked as well as a protected next mapping. This correction is scoped to string loads; it does not close the broader scalar/FP/vector wide-access audit. The [PowerPC Programming Environments manual](https://www.nxp.com/docs/en/user-guide/MPCFPE_AD_R1.pdf), section 3.2.2, permits string operations to fault/restart after crossing a page/BAT/segment boundary.

Native string stores now finish every successful byte in the instruction after a completed SMC notification. A later DSI takes precedence, keeps the committed prefix and suppresses the following instruction. When a completed string extends beyond the active code page, VERIFY compares the last SMC observation rather than incorrectly treating its final ordinary byte store as the exit address. Failure captures retain that same precise exit metadata.

The independent fixture now runs actual `nw_jit_try` production dispatch with selective register copying, native tail callbacks and the C successor loop. Explicit expected GPR/FPR/VR state checks cover integer-to-FP-to-integer transitions, untouched registers, FP-disabled successors, pending DEC and CPU events. Chained string load/store faults deliver real CPU DSI state with the successor's SRR0, logical DAR, store direction and completed prefixes. The fixture disables only the native-tail callback in its own process to exercise the C path, then restores it. These selected cases pass; full selective-mask/vector/system/reservation transition coverage remains open.

## Atomic translation and reservation milestone

`lwarx` and `stwcx.` now enter the live VERIFY allowlist. The ordered tape distinguishes address-translation observations from actual memory transactions. A conditional store consumes its store-permission/PA observation even when no reservation matches and no memory transaction occurs. Its success decision is computed from the private reservation and recorded PA; it is not copied from the reference's CR result. Wrong observation types, widths, addresses/order and store values fail comparison. Replay owns no live CPU, populated DTLB, MMU or device callback.

Each VERIFY boundary copies the real starting reservation into the shadow, and comparison includes the resulting valid bit and physical address. This preserves a reservation across separate blocks and allows different logical addresses mapping to the same physical word. Failed translations preserve old CR, register outputs and reservation; a completed conditional SMC store clears the reservation, sets EQ/SO and exits before its suffix. The current policy matches KPX's aligned single-CPU word-address model. The [PowerPC Programming Environments manual](https://www.nxp.com/docs/en/user-guide/MPCFPE_AD_R1.pdf), instruction listings and memory-synchronization section, documents physical-address association and preservation across exceptions. KPX's chosen failed-address-mismatch result is an existing emulation policy, not a newly claimed hardware granule model. Misaligned operations, DMA/other-agent granule invalidation and multiprocessor coherency still require broader work.

Production atomic callbacks previously bypassed memory-bank/device decoding and used raw host accesses at the translated PA. The independent device fixture reproduces a host SIGSEGV before repair (`/tmp/macemu-ppc-atomic-baseline-core.log`). Reads/stores now use the device decoder exactly once, reject an unmapped PA before dereferencing it, and retain the existing ignored-ROM-store policy. Literal ROM tests check unchanged bytes, conditional success and reservation clearing; private and production destructive-device tests count exactly one read and one successful store. This is callback coverage, not a complete certificate of all physical-bus fault delivery.

Captures use `NW-PPC-VERIFY 2`, adding typed translation records and initial/reference/native reservation state, without host addresses. Offline replay accepts both versions. `ppc_verify_atomic_alias.capture` is a checked-in three-instruction literal regression that loads through one logical address and conditionally stores through another mapping to the same PA. Both the old conversion capture and this new capture run with every core suite. Complete originally cached source capture and automatic minimization remain open.

Independent production checks exercise native tails and the C successor loop with aliasing conditional stores, reservation mismatches, protected-store DSI and pending DEC stops between reservation creation and conditional storage. Live CPU exception fields and completed prefixes are checked explicitly. These extend the prior integer/FP/string transition tests; vector/system transitions remain outside this milestone.

## Selected integer VMX and vector-memory replay

The first VMX revisit milestone admits **41 named integer/permutation/VSCR forms** (39 names plus two record forms) and **12 vector memory/shift-mask forms** to isolated VERIFY. Named helpers and their existing NEON equivalents read and write private `nw_jit_cpu` vector state. Delegated `nw_jit_helper_vmx` calls remain forbidden during replay because they borrow the live KPX CPU; vector FP is also outside this milestone. The verifier uses a positive opcode allowlist rather than admitting all primary-opcode-4 instructions.

Independent comparisons exposed three real helper defects: `vsumsws`, `vmsumshs` and `vpkswss` produced correctly clamped values but omitted VSCR's sticky SAT update. Each helper now sets SAT on saturation, preserves an already-set SAT, and leaves other VSCR bits intact. `mtvscr` still owns explicit clearing. These behaviors follow the [AltiVec manual's VSCR and saturating-instruction definitions](https://www.nxp.com/docs/en/reference-manual/ALTIVECPEM.pdf). The baseline fixture reports **1,335 failed assertions**, including the then-forbidden verification forms and reproduced SAT discrepancies (`/tmp/macemu-ppc-vector-baseline-core.log`). A one-instruction captured `vsumsws` alias failure is checked in as `SheepShaver/src/kpx_cpu/tests/ppc_verify_vector_sat.capture` and replayed automatically.

KPX records the logical, aligned 16-byte translation probe for `lvx/lvxl/stvx/stvxl`, followed by the four actual ordered word transactions. Private replay consumes these observations without consulting host MMU, DTLB, RAM or devices. Full-vector loads stage all words until replay succeeds. Full-vector stores consume the whole completed instruction after SMC, retain the last SMC subaccess and let a later fault take precedence. Element loads/stores consume ordinary byte/halfword/word observations and retain untouched lanes. `lvsl/lvsr` use only the logical effective address. ## P4 system observations and P5 branch successors (October 3)

P4 replaces live-CPU delegation for supported system operations with a typed service boundary. Ordered observations contain the exact instruction PC and opcode, independently computed operands, returned values and explicit success/no-op/privilege/trap/syscall/DSI/SMC outcomes. Private replay validates and consumes this tape without invoking a shared CPU callback. SPR, TB/DEC, segment/BAT, MMU and cache services execute once in the reference/live path. This checks instruction ownership and use of observed services; it does not independently certify MMU translation, timer hardware or every service implementation.

## P6 first scalar milestone: conversion, comparison and bit-preserving moves (October 3)

## P6 round-to-single milestone (October 3)

`frsp` now implements the modeled PPC rounding and status behavior instead of delegating its architectural result to a host `double -> float` cast. NaN payloads project into the upper 35 source bits with the lower 29 bits cleared; signaling inputs accrue VXSNAN and are quieted when VE is disabled. With VE enabled, the destination and FPRF remain unchanged while FR/FI clear. Finite values round to 24-bit precision under all four guest RN modes. Each operation replaces FR/FI, records new sticky causes and recomputes VX/FEX; valid results update FPRF even when VE is enabled. Zero clears FR/FI; infinity preserves them according to the instruction model. Disabled overflow chooses FR=0 as an explicit implementation profile because the architecture leaves it undefined.

Enabled underflow and overflow store the rounded significand with exponent adjustments of +192 and -192 respectively; disabling MSR FP delivery does not turn those results into ordinary IEEE single overflow/underflow. Enabled underflow records UX even for exact tiny inputs. Disabled underflow uses gradual single precision and detects tininess before rounding, including a rounded result that becomes the minimum normal single. Disabled overflow stores signed infinity or maximum finite single according to RN and records OX/XX/FI. The independent numeric reference uses `frexp`/`nearbyint`/`ldexp`; the native/local-C kernel rounds integer significands and constructs raw result bits. ## P6 finite multiply rounding and exception results

The next bounded finite-arithmetic slice implements `fmul`/`fmuls` rounding and result status. The native kernel forms the exact 106-bit product of the two finite double significands, keeps its exponent unbounded, and rounds once to 53 or 24 bits. Disabled underflow denormalizes before rounding and raises UX only for an inexact tiny result, using pre-rounding tininess; enabled underflow raises UX for every nonzero tiny intermediate and delivers the rounded significand with its exponent increased by 1536 or 192. Enabled overflow subtracts those same precision-dependent exponent adjustments. Disabled overflow delivers RN/sign-dependent infinity or maximum finite, sets XX/FI and chooses FR=0 within the architecture's undefined profile. XE, OE and UE results commit before the selected FE program exception; instruction PC ownership and suffix suppression reuse the qualified arithmetic publication path.
